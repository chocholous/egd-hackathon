64	### A) Klikání v prohlížeči (vlastník webu) ✅ — doporučeno pro začátečníka
65	
66	Prošlo v české UI pod vlastnicí webu, logy a screenshoty `sondy/ms-prava/ui/` (časy jsem neměřil ručně ❓).
67	
68	1. **Úrovně:** ozubené kolo → **Oprávnění k webu** → dole **Rozšířené nastavení oprávnění** → pás karet
69	   **Úrovně oprávnění** → klikni **Přispívání** → dole **Zkopírovat úroveň oprávnění** → Název `EGD Schvalovatel`
70	   → zaškrtni **Přepsat rezervaci a uživatelské nastavení** → **Vytvořit**. Totéž znovu s názvem `EGD Zadavatel`
71	   bez zaškrtnutí (kopie dá přesně práva Přispívání, `sondy/ms-prava/urovne.json`).
72	   Schvalovatel nemá mazat? Při kopii navíc odškrtni **Odstranit položky** ✅ (úroveň „EGD Schvalovatel UI bez mazání“
73	   má stejné bity jako z CLI, `Low` 1011028967 = bez `DeleteListItems`; `sondy/ms-prava/ui/40-*`, `ui/41-*`).
74	   *Funguje?* Na stránce Úrovně oprávnění jsou obě nové úrovně. *Ne (chybí odkaz / chyba přístupu)?* Nejsi vlastník → D.
75	   *Ne (chyba při Vytvořit, politika tenantu)?* → C.
76	2. **Skupiny:** Rozšířené nastavení oprávnění → **Vytvořit skupinu** → Název `<Appka> Zadavatelé` → dole v části
77	   „Poskytnout skupině oprávnění k tomuto webu“ zaškrtni **Čtení** → **Vytvořit**. Totéž pro Schvalovatelé a Správci.
78	   Lidi: na stránce skupiny **Nový** → jméno nebo e-mail → **ZOBRAZIT MOŽNOSTI** → odškrtni „Poslat pozvánku
79	   e-mailem“ → **Sdílet**. Sebe ze skupin Zadavatelé a Schvalovatelé odeber: na stránce skupiny zaškrtni svůj řádek →
80	   **Akce** → **Odebrat uživatele ze skupiny** → potvrď dialog ✅ (`sondy/ms-prava/ui/43-*`).
81	   Zaškrtnutí **Čtení** ve formuláři Vytvořit skupinu dá skupině Čtení na webu ✅ (`ui/42-*`, kontrola
82	   `_api/web/roleassignments`). Zapomněl jsi ho? Dodatečně: Rozšířené nastavení → **Udělit oprávnění** → skupina →
83	   ZOBRAZIT MOŽNOSTI → Vybrat úroveň oprávnění **Čtení** → Sdílet ✅ (`ui/31-*.log`).
84	3. **Seznam:** v seznamu ozubené kolo → **Nastavení seznamu** → **Oprávnění pro: Seznam** → **Ukončit dědění oprávnění**
85	   → potvrď → zaškrtni Členy a Návštěvníky webu → **Odebrat uživatelská oprávnění** → potvrď → **Udělit oprávnění** →
86	   název skupiny → ZOBRAZIT MOŽNOSTI → odškrtni pozvánku → **Vybrat úroveň oprávnění** (EGD Zadavatel / EGD Schvalovatel /
87	   Úplné řízení pro Správce) → **Sdílet**. Vlastníci webu na seznamu zůstanou.
88	   *Funguje?* Na stránce oprávnění seznamu je „Pro tento seznam jsou nastavena jedinečná oprávnění“ a 4 řádky
89	   (Vlastníci + 3 skupiny). *Ne (tlačítko Ukončit dědění chybí)?* Nejsi vlastník → D.
90	4. **Jen své:** Nastavení seznamu → **Upřesnit nastavení** → Přístup pro čtení **Číst položky vytvořené daným uživatelem**,
91	   Přístup pro vytváření a úpravy **Vytvořit položky a upravit položky vytvořené daným uživatelem** → dole **OK**.
92	
93	*Funguje?* Kontrolní příkaz v části Ověření vrátí `2, 2, true`. *Ne?* Zopakuj krok, jehož hodnota nesedí
94	(`ReadSecurity`/`WriteSecurity` ≠ 2 → krok 4; `HasUniqueRoleAssignments` false → krok 3).

97	pozvánku e-mailem. Co chce od IT E.ON: jen roli Vlastník webu (viz D). Obtížnost pro citizen developera: nízká až střední.

115	
116	```powershell
117	$W = "<web>"; $S = "<Seznam>"; $A = "<Appka>"

120	m365 spo roledefinition add --webUrl $W --name "EGD Schvalovatel" --rights "$Z,CancelCheckout"   # bez mazání: z $Z vyndej DeleteListItems
121	m365 spo group add --webUrl $W --name "$A Zadavatelé"          # totéž Schvalovatelé, Správci
122	m365 spo group member add --webUrl $W --groupName "$A Zadavatelé" --userNames "a@firma.cz,b@firma.cz"
123	m365 spo web roleassignment add --webUrl $W --groupName "$A Zadavatelé" --roleDefinitionName "Čtení"   # pro všechny 3 skupiny
124	m365 spo list roleinheritance break --webUrl $W --listTitle $S --clearExistingPermissions --force
125	m365 spo list roleassignment add --webUrl $W --listTitle $S --groupName "<Vlastníci webu …>" --roleDefinitionName "Úplné řízení"
126	m365 spo list roleassignment add --webUrl $W --listTitle $S --groupName "$A Zadavatelé" --roleDefinitionName "EGD Zadavatel"
127	m365 spo list roleassignment add --webUrl $W --listTitle $S --groupName "$A Schvalovatelé" --roleDefinitionName "EGD Schvalovatel"
128	m365 spo list roleassignment add --webUrl $W --listTitle $S --groupName "$A Správci" --roleDefinitionName "Úplné řízení"
129	m365 spo list set --webUrl $W --title $S --readSecurity 2 --writeSecurity 2
130	```

174	Pomocné metody, které úryvek používá (z téhož souboru; `SPHttpClient` z `@microsoft/sp-http`):
175	
176	```ts
177	private _url(cesta: string): string {
178	  const seznam = (this.properties.seznam || '<Seznam>').replace(/'/g, "''");
179	  return `${this.context.pageContext.web.absoluteUrl}/_api/web/lists/getbytitle('${encodeURIComponent(seznam)}')${cesta}`;
180	}
181	private async _cti<T>(cesta: string): Promise<T> {
182	  const r = await this.context.spHttpClient.get(this._url(cesta), SPHttpClient.configurations.v1,
183	    { headers: { Accept: 'application/json;odata=nometadata' } });
184	  if (!r.ok) throw new Error(`SharePoint vrátil ${r.status}`);
185	  return (await r.json()) as T;
186	}
187	```
188	
189	```ts
190	const PRAVO_VSE = 0x100;      // CancelCheckout (Přepsat rezervaci…) = vidí a upraví cizí → schvalovatel
191	const PRAVO_PRIDAT = 0x2;     // AddListItems
192	const PRAVO_SPRAVA = 0x800;   // ManageLists → správce
193	
194	// v _nacti() (this._cti čte /_api/web/lists/getbytitle('<Seznam>') + cesta):
195	const prava = await this._cti<{ High: string; Low: string }>('/EffectiveBasePermissions');
196	const low = Number(prava.Low);
197	this._schvalovatel = (low & PRAVO_VSE) !== 0;
198	this._muzePridat = (low & PRAVO_PRIDAT) !== 0;
199	this._spravce = (low & PRAVO_SPRAVA) !== 0;
200	// záložku „Ke schválení“ ukaž jen když this._schvalovatel; formulář jen když this._muzePridat
201	```
202	
203	**Nepoužívej `ApproveItems` (0x10)** jako znak schvalovatele: úroveň EGD Schvalovatel ho nemá (Eva má `Low=0x3c4313ef`,
204	bez 0x10) a záložka by se neukázala. Všechny použité bity jsou v `Low` ✅ (`High` je u zadavatele i schvalovatele `0x3b0`;
205	`sondy/ms-prava/clen-test.jsonl`). Při `ReadSecurity=2` vrací seznam zadavateli jen jeho položky sám; filtr `AuthorId`
206	v kódu už není potřeba (ale neuškodí). Čteš-li víc než jednu stránku, hledej další stránku pod `@odata.nextLink`
207	i `odata.nextLink` (SPFx `SPHttpClient` posílá OData 4.0; důkaz `skills/egd-data-seznamy/TEST-copilot.md` ř. 39–43).

40	## Skript
41	
42	Všechno dělá skript `scripts\appka.mjs` (bez závislostí; celá cesta A chce **Node 22.14+, 24 nebo 26**
43	kvůli SPFx 1.24 a CLI). **`<A>` = úplná cesta k tomu
44	souboru**: vezmi složku, ze které jsi načetl tenhle SKILL.md, a připoj `scripts\appka.mjs`
45	(typicky `%USERPROFILE%\.claude\skills\egd-prvni-appka\scripts\appka.mjs`, u Copilota
46	`%USERPROFILE%\.copilot\skills\...` nebo `.github\skills\...` v otevřené složce). Ověř, že
47	soubor existuje; složka skillu může ležet kdekoli, rozhoduje to, odkud jsi SKILL.md četl.
48	
49	Spouštěj ho **vždy z pracovní složky z `egd-pripravenost`** = složka, ve které je podsložka
50	`.pripravenost` (obvykle `%USERPROFILE%\egd-workshop`, může se jmenovat jinak). Tam leží výsledek
51	kontroly a lokálně nainstalované CLI for Microsoft 365, které skript najde sám. Projekt appky
52	vznikne jako její podsložka `prvni-appka`.
53	
54	```
55	node "<A>" <prikaz> [volby]      # node "<A>" --help vypíše všechno
56	```
57	
58	Kódy: 0 hotovo, 1 chyba, 2 špatné použití, 10 plán bez zápisu. Řádky začínají `[OK]`, `[INFO]`,
59	`[POZOR]`, `[CHYBA]`; u chyby následuje `co dal:` a případně `veta pro IT:`. Výpis skriptu je bez
60	diakritiky schválně (konzole Windows); uživateli piš normálně česky. S `--ano` skript plán vypíše
61	znovu a hned za ním zapisuje - to je v pořádku.
62	
63	**Windows / PowerShell 5.1:** cesty vždy v uvozovkách, jen ASCII uvozovky, nepřesměrovávej `2>&1`,
64	výstup nečti přes `| Select -First`. `npm`, `npx` ani `m365` přímo nevolej (execution policy,
65	cizí balíček `m365` na npm) - vše jde přes `node "<A>"`.

116	### K jednotlivým krokům
117	
118	- **Krok 1.** Šablona je hotový SPFx 1.24.1 projekt bez frameworku (čisté TypeScript + SCSS,
119	  bez Reactu) s `package-lock.json`, takže `npm ci` nainstaluje přesně ověřené verze ✅. Každý projekt
120	  dostane nové GUIDy, dva účastníci si appky nepřepíšou. `yo` ani generátor nejsou potřeba.
121	  Spadne-li na Node, certifikátu nebo síti, skript vypíše větu pro IT → cesta B.
122	- **Krok 2.** Build je Heft (`npm run build`), gulp od SPFx 1.24 neexistuje 📘. Chyby jsou celé
123	  v `prvni-appka\build.log`. Varování lintu (`Warning:`) nevadí, chyby (`Error`, `TS####`) ano.
124	- **Krok 3.** Seznam `Spokojenost`: sloupce Hodnocení (číslo 1–5, povinné, formátované jako barevný
125	  štítek) a Den (text `RRRR-MM-DD`, podle něj appka sčítá dny). Kdo hlasoval, si SharePoint pamatuje
126	  sám (Vytvořil). Interní názvy jsou bez diakritiky (`Hodnoceni`, `Den`); appka je čte podle nich.
127	- **Krok 4.** Skript sám: ověří přihlášení a katalog webu, nahraje balíček (`spo app add
128	  --appCatalogScope sitecollection --appCatalogUrl <web> --overwrite`), `deploy`, `install`
129	  (nebo `upgrade`, když appka na webu už je), založí stránku v jediném funkčním pořadí
130	  **Article → sekce → web part → SingleWebPartAppPage + publish** ✅ a přečte ji zpátky. Hlášku
131	  „There is no available WebPart with Id“ hned po instalaci čeká a zkouší znovu - je to propagace,
132	  ne chyba práv (20 s až 1 min ✅ změřeno 5.–6. 11. při stavbě skillu `spfx-ship`; v testech tohoto
133	  skillu propagace nenastala, čekací smyčka skriptu je proto ❓).
134	- **Krok 5.** Skript vypíše dvě adresy. Uživateli dej tu s `?env=WebView` (appka na celé okno, bez
135	  rámu SharePointu ✅). Ověření níže. `rc=0` ani `[OK]` nestačí - hotovo je to, co člověk viděl.

160	## Co se v appce dá změnit hned potom (vibecoding)
161	
162	Kód je v `prvni-appka\src\webparts\spokojenost\SpokojenostWebPart.ts` (logika) a
163	`SpokojenostWebPart.module.scss` (vzhled EG.D: indigo `#1200E0`, inkoust `#261B62`). Typické první
164	úpravy a jejich postup: [references/upravy.md](references/upravy.md). Po každé změně
165	`build` a `nasadit --ano` (plán ukaž znovu); `nasadit` nahraje novou verzi a udělá `upgrade`.

167	může dál ukazovat starý kód ❓ (pozorováno u jiné appky: bez `upgrade` zůstala stará verze).
